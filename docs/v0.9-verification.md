# v0.9 reproducibility — verification

2026-10-04. Scope: MASTER-PLAN sections 74–78 and the v0.9 milestone.

## Implementation

Cases retain the existing versioned case schema and now carry an optional versioned reproducibility manifest: normalized redacted export SHA-256, fixed fixture bytes SHA-256, canonical experiment definition SHA-256, explicit 1280x720 viewport, headless/fresh-context/service-worker settings, collection and runtime limits, allowlisted hosts/private-subnet denies and methodology versions. Model configuration, actual routed model, response IDs, evidence, actions, usage and timestamps remain in the accompanying case. Manifest settings describe the requested execution configuration; failed or unavailable collection stays explicit.

Sorted object keys and preserved array order define sorted-json-v1. The digest covers all normalized case data and manifest fields except the digest itself. Digests are consistency checks, not signatures, identity verification or proof of truth. Page excerpt digests may precede export redaction. Unknown top-level fields outside the normalized schema are not covered. Dynamic model routing, target resources, timing and shared sandbox state prevent guaranteed identical reruns. JSON is the replay record; Markdown summarizes findings, exact references, hypotheses, limitations and reproduction steps. No PDF, persistent case database, arbitrary-target enablement or public file upload was introduced.

The loader validates limits/schema and checks manifest consistency before replacing the current case. Tampering rejects the file while retaining the previous case. Legacy cases remain readable with an explicit missing-digest message. Browser displays evidence as inert text; loading does not investigate a target. Reports include fingerprints and budget usage.

## Remaining stability gate

The current free router has repeated network failures or missing structured research output across routed models. Before claiming stable v1 AI behavior, validate a fixed provider/model capable of the strict tool schema using repeatable controlled runs. Keep failure visibility and all isolation policies. Broader reliability/load validation and source release capture also remain: the working tree is uncommitted/unpushed, so an engine version plus image/fixture fingerprints is not a complete immutable source archive. No identical-rerun, authenticity, maliciousness or full v1 stability claim is made.
