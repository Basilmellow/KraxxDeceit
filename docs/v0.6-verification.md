# v0.6 bounded AI research agent — verification

Date: 2026-10-04. Scope: MASTER-PLAN sections 70–73.

## Implementation

- Production browser pipeline enables a bounded research loop: observe, propose a
  concise public question/hypothesis, choose one safe browser tool, record its result,
  reassess prior evidence and stop. No shell, filesystem, credential or unrestricted
  command tool was added. Existing sandbox destination and resource policies remain.
- Model tool arguments include a strict research assessment with recorded evidence IDs.
  Unknown/missing IDs stop before dispatch. Hypothesis statuses are model interpretations;
  no engine-verified causation is claimed. Deterministic fallback is labeled engine-origin.
- Evidence includes bounded untrusted page excerpts, exact tool-result/action references
  and a read-only view of eligible live investigation events. Snapshot digests describe
  the original bounded text; subsequent export redaction may alter an excerpt.
- Explicit stops: sufficient evidence, no useful experiment, experiment/tool/model budget,
  timeout, safety policy, model/tool error, invalid evidence. Repeated identical tools on
  unchanged URL/text stop before the third dispatch. Safety violations stop research mode.
- Failed browser results are no longer marked completed. Context reads and URL validation
  share the runtime deadline; dispatch is checked again after validation.
- Initial caps: 5 experiments, 10 dispatched browser tools, 8 provider turns, 60 seconds,
  4096 provider output tokens per turn, 30 retained research evidence records. Page input
  remains 16000 bytes; excerpt output 1200 characters. Existing event/case size caps apply.
  These are conservative initial caps, not a claim of optimal benchmarked values.
- Research UI displays questions, evolving assessments, results, source evidence, budgets,
  failure codes and stop reasons. No private model reasoning is retained or rendered.

## Provider diagnosis

Read-only metadata for prior v0.5 generation confirmed finish_reason `length`, 500 native
reasoning tokens and 580 completion tokens. The old 500-token request allowance was
insufficient for visible tool output. Raised the bounded allowance to 4096, requested one
research tool call, disabled parallel suggestions and reject multiple returned calls.
Output-limit errors retain model/response provenance and expose a precise failure code.
No silent provider switch, retry loop or automatic increase beyond the caps was added.
